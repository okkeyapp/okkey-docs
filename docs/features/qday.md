# Q-Day ready

Q-Day ready в Okkey - это не отдельный переключатель в интерфейсе, а политика криптографии ядра: с первого продакшена новые записи пишутся профилем v2, без тихого отката на более слабый профиль. Enterprise не может эту политику подменить.

## Какие профили есть

Реестр в `packages/crypto/src/config`:

| Профиль | Режим | Где разрешён |
| --- | --- | --- |
| v1 | `dev_test_legacy`, классический | только `dev` и `test` |
| v2 | `qday_default`, гибридный конверт | `dev`, `test`, `stage`, `prod` |

Для `stage` и `prod` новые записи - только v2. v1 оставлен для явных dev/test-фикстур. Self-host compose по умолчанию ставит `DEPLOY_ENV=dev` и `CRYPTO_ALLOWED_PROFILE_VERSIONS=1,2`, потому что веб-регистрация всё ещё передаёт `password_kdf_params_version=1`, а сам identity blob уже v2. `DEPLOY_ENV=prod` разрешает только профиль 2 и отвечает `CRYPTO_PROFILE_NOT_ALLOWED`. Сочетание `CRYPTO_ALLOWED_PROFILE_VERSIONS=1,2` и `DEPLOY_ENV=prod` процесс не пускает.

## Алгоритмы, которые реально вызываются

Движок - `rust/crypto-engine`, в клиенты собирается в WASM. Открытый код и архитектурные заметки фиксируют такие примитивы:

- **Argon2id** - доля мастер-пароля (KDF).
- **XChaCha20-Poly1305** - симметричное шифрование записей сейфа, вложений и payload гибридного конверта. Nonce 24 байта.
- **AES-256-GCM** - объявлен среди примитивов движка.
- **X25519** - эфемерный ECC-ключ в гибридном конверте, 32 байта.
- **ML-KEM-768** - постквантовая инкапсуляция. Ciphertext в конверте - 1088 байт. Пара ключей пользователя: decapsulation + encapsulation.
- **Ed25519** - подписи. Критичные события синхронизации (`VAULT_SHARE`, `VAULT_KEY_ROTATION` и операции share/revoke/rotate/update-role) подписываются гибридным конвертом `hybrid_ed25519_pq_bind_v1`: Ed25519 плюс привязка к PQ-ключу подписанта.
- **HKDF / SHA-256** - KDF гибридного конверта: `SHA-256(domain || ecc_shared || pq_shared || aad)`, идентификатор `kdf_id = 1`.
- **OS RNG** - генерация ключей и значений генератора.

Гибридный конверт v2 (версия заголовка `1`, `aead_id = 1` = XChaCha20-Poly1305) склеивает ECC- и PQ-секреты. Расшифровка выбирается по проверенным возможностям, без тихого понижения. JS-запасного пути для hybrid/PQ нет: ошибки WASM становятся `CryptoSdkError` с кодами `UNSUPPORTED_ALGORITHM`, `INVALID_KEY_LENGTH`, `MALFORMED_ENVELOPE`, `DECRYPT_FAILED`, `INTERNAL`.

Идентичность пользователя в v2 - связка Ed25519 и ML-KEM-768 (`ed25519_mlkem768_v1`). Приватный набор шифруется, открытый PQ-ключ хранится отдельно.
