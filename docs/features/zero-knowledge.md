# Нулевое хранение

Сервер не видит расшифрованные записи, мастер-пароль и целый ключ хранилища. Шифрование и расшифровка выполняются только на клиенте. Администратор self-hosted сервера тоже не читает содержимое сейфов: образы API, worker и web эту схему не меняют.

Цепочка для данных сейфа:

1. Клиент шифрует.
2. Сервер сохраняет шифротекст, события и метаданные.
3. Клиент расшифровывает.

## Что сервер всё же хранит

Это не секреты записей, но и не пустая база:

- PostgreSQL: пользователи, устройства, метаданные сейфов, журнал событий.
- Redis: сессии, кэш, блокировки, очередь писем.
- S3-совместимое хранилище (в compose - MinIO): зашифрованные вложения и файлы.

Почта с кодом входа уходит с сервера (или пишется в лог worker, если `EMAIL_PROVIDER=logger`). Код подтверждения - не содержимое сейфа, но сервер его создаёт и доставляет.

Для капсул опциональный GeoIP режется локально по MMDB. IP заявителя на сторону третьей стороны не отправляется. В прод-compose GeoIP по умолчанию выключен (`GEOIP_ENABLED=false`).

Проверка скомпрометированных паролей отправляет только префикс SHA-1 в Have I Been Pwned. Это единственный описанный в интерфейсе исходящий запрос, связанный с паролем записи. Полный пароль в нём не участвует.

## Чего сервер не делает

Криптография не переносится на бэкенд. Плагины Enterprise не могут переопределить криптопотоки ядра, политику версии и обнуление ключевого материала сейфа.
