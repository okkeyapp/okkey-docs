# Почта

Почта нужна кодам входа, приглашениям и заявке на тариф. Страница для тарифа «Бесплатный» и тарифа «Предприятие» на вашей машине.

Первому аккаунту на пустой базе письмо не нужно. Со второго входа сервер присылает код из 6 цифр. См. [первую настройку](../getting-started/first-setup.md).

## Пока SMTP не задан

Установщик пишет в `.env` значение `EMAIL_PROVIDER=logger`. Письма никуда не уходят. Воркер печатает их в свой лог. Так и задумано при `DEPLOY_ENV=dev`, который установщик оставляет по умолчанию.

```bash
cd ~/okkey
docker compose -p okkey -f docker-compose.prod.yml --env-file .env logs -f worker
```

Ищите строку `email sent`. Код лежит в поле `plainText`. В теме письма цифры кода скрыты. Если каталог не `~/okkey`, подставьте имя каталога в нижнем регистре вместо `okkey`.

Приглашение участника без настроенной почты и без публичного адреса приложения не сохраняется. Заявка на тариф уходит на `OKKEY_SALES_EMAIL` из `.env`. Этот адрес задаётся при установке, в окне «Почта сервера» его нет.

## Почта сервера в настройках

SMTP и публичный адрес приложения задаёт владелец пространства. Раздел виден только на self-hosted и только владельцу. Откройте «Настройки», «Основное». Блок называется «Почта сервера». Подпись блока: «Эти параметры действуют для всего сервера, а не только для этого пространства.»

| Поле | Подпись |
| --- | --- |
| SMTP-сервер | Имя сервера. |
| Порт | Целое число от 1 до 65535. |
| Шифрование | «Нет», «STARTTLS» или «TLS». |
| Имя пользователя | Учётная запись SMTP. |
| Пароль | Если пароль уже сохранён, поле можно оставить пустым. Подсказка: «Оставьте пустым, чтобы сохранить текущий пароль». Рядом будет «Пароль сохранён». |
| Адрес отправителя | Адрес в поле From. |
| Публичный URL приложения | Адрес, с которого люди открывают Okkey. Ссылки в приглашениях собираются от него. |

Кнопка «Сохранить» записывает блок. Кнопка «Отправить тестовое письмо» шлёт письмо на адрес владельца. Успех: «Тестовое письмо отправлено». Для теста нужны сервер, порт, шифрование и адрес отправителя.

Пустой блок берёт значения из `.env`: `EMAIL_SMTP_HOST`, `EMAIL_SMTP_PORT`, `EMAIL_SMTP_SECURE`, `EMAIL_SMTP_USER`, `EMAIL_SMTP_PASSWORD`, `EMAIL_FROM`, `PUBLIC_APP_URL`. То, что сохранено в «Почте сервера», для отправки важнее этих переменных. Пароль в базе запечатан секретом `SESSION_SECRET`. В ответ сервера сам пароль не возвращается.

Пока в блоке нет своего SMTP-сервера и в `.env` стоит `EMAIL_PROVIDER=logger`, коды по-прежнему пишутся в лог воркера.

## Если пароль SMTP перестал читаться

Пароль в настройках открывается ключом от `SESSION_SECRET`. После смены этого секрета старая запись не открывается. Над полями будет текст: «Сохранённый пароль SMTP не удаётся прочитать после смены секрета сервера. Введите его снова.»

Введите пароль заново и нажмите «Сохранить». Либо нажмите «Удалить сохранённый пароль». Тогда для отправки снова берётся пароль из `.env`, если он там задан.

## Приглашения и воркер

Приглашению нужны публичный адрес приложения и почтовый транспорт. Ссылка в письме живёт 14 дней. См. [Участники](../workspace/members.md).

Письма из API попадают в очередь Redis. Отправляет их воркер. Если воркер остановлен, письма ждут в очереди.

Тот же воркер убирает просроченное:

- раз в час стирает записи, которые лежат в корзине дольше срока из настроек пространства, и их файлы;
- раз в минуту удаляет капсулы, у которых вышло время удаления, и связанные файлы.

Срок корзины задаётся в «Настройки», «Записи». См. [Настройки пространства](../workspace/index.md).

## Как проверить

1. Войдите владельцем. В «Настройки», «Основное» есть блок «Почта сервера». Участник с ролью «Пользователь» этот блок не видит: у него нет «Настроек».
2. Заполните сервер, порт, шифрование, отправителя и публичный URL. Нажмите «Отправить тестовое письмо». На почту владельца приходит письмо «Okkey SMTP test».
3. Без SMTP зайдите вторым разом и выполните команду логов выше. В `plainText` есть код.
4. `docker compose -p okkey -f docker-compose.prod.yml --env-file .env ps` показывает `worker` в состоянии running.
