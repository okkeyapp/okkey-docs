# Максимальная защищённость

Записи шифруются на вашем устройстве. Сервер проверяет вход, синхронизирует изменения и хранит шифротекст. Открытый текст записей и целый ключ сейфа на сервер не попадают.

## Разделённый ключ

Ключ доступа собирается из трёх долей:

| Доля | Где лежит |
| --- | --- |
| Доля сервера | На сервере. Одной этой доли мало, чтобы открыть сейф. |
| Доля устройства | Ключ, которым её открывают, остаётся на устройстве. На сервере с 1.0.0-beta.3 эта доля хранится только в запечатанном виде. |
| Доля пароля | Считается из мастер-пароля. Сам пароль на сервере не хранится. |

Чтобы открыть хранилище, клиент забирает долю сервера, читает долю устройства, считает долю пароля и только потом расшифровывает ключи сейфов.

С 1.0.0-beta.3 утечка базы или бэкапа сервера не позволяет перебирать мастер-пароль офлайн. Подробнее на странице [Утечка базы сервера](./server-db-leak.md).

## Ключи сейфов и записей

У каждого сейфа свой ключ. Записи внутри сейфа шифруются этим ключом. Файлы шифруются отдельно и лежат в хранилище уже в зашифрованном виде.

При смене доступа ключ сейфа поворачивается заново.

## Что ещё ограничивает доступ

- Новое устройство не откроет хранилище, пока вы не подтвердите его на уже доверенном устройстве.
- Вход по email идёт через одноразовый код. Для самого первого аккаунта код не нужен.
- Второй фактор: «Приложение-аутентификатор» и «Резервные коды».
- Хранилище открывается мастер-паролем. На этом устройстве можно включить PIN из 6 цифр и биометрию. Они на другие устройства не копируются.
- Для отдельных зон можно снова спрашивать подтверждение: «Записи», «Капсулы», «Мониторинг», «Инструменты», «Настройки хранилища», «Мои настройки», окна записей, капсул, сейфов и папок, действие «Удаление».
- Профиль решает, какие записи видит участник. Роль решает, какие настройки пространства ему доступны.

Проверка паролей в мониторинге идёт на устройстве. В сервис утечек уходит только начало хеша, сам пароль устройство не отправляет. Подробнее в разделе [Мониторинг](../monitoring.md).
