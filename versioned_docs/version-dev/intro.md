# О проекте

Okkey — менеджер паролей с шифрованием на клиенте. Открытый репозиторий `okkey` содержит ядро, которое должно работать без кода Enterprise. Клиенты ядра: веб-приложение, мобильное приложение, десктоп и браузерное расширение. Развёртывание задумано и как SaaS, и как self-hosted.

Эта документация сверена с веткой `dev` открытого репозитория [okkeyapp/okkey](https://github.com/okkeyapp/okkey). Приватный репозиторий `okkey-enterprise` при подготовке сайта был недоступен, поэтому поведение модулей Enterprise описано только там, где его фиксирует ядро (заглушки, матрица тарифов, архитектурные заметки). ## Как устроен продукт

В терминах ядра:

- **Пользователь** — учётная запись.
- **Устройство** — доверенное устройство входа. Новое устройство нужно явно подтвердить.
- **Пространство** (workspace) — группа сейфов и участников. В self-hosted у владельца может быть не больше одного пространства.
- **Сейф** (vault) — контейнер записей со своим ключом.
- **Запись** (item) — логин, карта, заметка и другие категории.
- **Папка** — личная группировка записей. Папки видит только их владелец.
- **Капсула** — зашифрованная передача текста, файла или записи по ссылке.

В боковом меню веб-приложения пункты называются так: «Все записи», «Капсулы», «Мониторинг», «Инструменты», «Настройки», секции «Сейфы» и «Папки».

## Главные свойства

| Свойство | Что это значит в коде |
| --- | --- |
| [Q-Day ready](./features/qday) | Продакшен-записи идут профилем `crypto_version` v2: гибрид X25519 и ML-KEM-768, AEAD XChaCha20-Poly1305. |
| [Защищённость](./features/security) | Ключ сейфа собирается из трёх долей. Сервер не хранит целый ключ и не видит открытый текст записей. |
| [Нулевое хранение](./features/zero-knowledge) | Шифрование и расшифровка выполняются на клиенте. Движок — Rust, в клиенты попадает как WASM. |
| [Открытый код шифрования](./features/open-source) | Криптография, сейфы и клиенты лежат в открытом `okkey`. Enterprise подключается плагинами и не подменяет криптополитику. |
