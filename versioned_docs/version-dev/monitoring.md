# Мониторинг

«Мониторинг» есть в боковом меню и на Free, и на Enterprise. Он нужен, чтобы вы видели слабые и повторяющиеся пароли, не отправляя сами пароли на сервер. На карточке бейдж «Beta».

Текст страницы: «Оценка безопасности рассчитывается на основе записей, к которым у вас есть доступ в текущем пространстве. Анализ выполняется локально и не предполагает сбора или передачи статистики о ваших данных.»

Пусто: «Пока нечего анализировать». «Добавьте записи с паролями в доступные сейфы - мониторинг рассчитает показатели локально на устройстве.» Кнопка «Перейти к записям». Если проблемы не нашлись: «Всё в порядке» и «По доступным вам паролям в этом пространстве проблем безопасности не найдено.»

Кнопка «Показать» открывает список записей с уже выбранным фильтром. «Назад к записям» возвращает к списку. Область сейфов на странице: «Все сейфы», «Личный», «Общие».

Какие карточки видны, задаёт пространство (`monitoring_card_settings`). По умолчанию включены все: общий показатель, надёжность, повторы, слабые, скомпрометированные, устаревшие, passkeys, 2FA. Выключенная карточка не штрафует оценку и не отдаёт список. Где в UI переключают карточки, в открытых строках отдельным экраном не подписано. **TODO:** найти экран «Настроить» (`web.monitoring.configure`) и описать его, если он подключён к этим флагам.

## Общий показатель

«Общий показатель». «Индикатор показывает общий уровень безопасности по всем доступным вам записям в пространстве».

Оценка 0–100. Подписи: от 90 «Отлично», от 70 «Хорошо», от 45 «Средне», ниже «Плохо». Если паролей нет, функция оценки возвращает 100, но пустой экран показывает «Пока нечего анализировать», а не эту сотню.

Штрафы от доли проблемных паролей (каждый выключенный тип карточки в штраф не входит):

| Проблема | Снимается до |
| --- | --- |
| Слабые | 40 |
| Средние | 15 |
| Повторно используемые | 25 |
| Устаревшие | 15 |
| Скомпрометированные | 35 |

В оценку не входят пробелы 2FA и passkeys.

## Карточки

Считаются пароли из записей, которые не в архиве и не удалены, в выбранных сейфах.

| Карточка | Как попадает запись |
| --- | --- |
| «Надёжность паролей» | Доли «сильные», «средние», «слабые». Энтропия в `getPasswordEntropyBits`: длина и набор символов, бонус за форму парольной фразы, штрафы за повторы, шаблоны `1234` / `abcd` / `qwerty` / `password` / `admin` / `letmein`, клавиатурные куски и почти один символ. Слабый - меньше 36 бит, средний в мониторинге - это метки fair и good (36–64 бит), сильный - strong и excellent (от 64). |
| «Повторно используемые пароли» | Один и тот же пароль в двух и более записях. «Один пароль может использоваться в нескольких аккаунтах.» |
| «Слабые пароли» | Бакет weak. «Слабые пароли могут быть недостаточно устойчивыми к подбору.» |
| «Скомпрометированные пароли» | Have I Been Pwned: на сервер уходит только префикс SHA-1, полный пароль устройство не передаёт. «Пароли, найденные в известных утечках данных.» |
| «Устаревшие пароли» | Пароль не менялся больше `STALE_PASSWORD_AGE_MS` - 365 суток. «Пароли, которые не менялись больше года.» |
| «2FA доступны, но не настроены» | У записи есть пароль, нет настроенного TOTP, а домен из URL есть в каталоге с `supports2FA`. Каталог качается открытым списком Okkey domain-capabilities. Подпись: «Источник: Data sourced from 2FA Directory by 2factorauth.» Если каталог пуст, список пуст. |
| «Passkeys доступны, но не настроены» | Карточка есть, текст обещает сервисы с passkeys. Список в коде всегда пустой, пока в записи не появится поле passkey и проверка каталога. **TODO:** не описывать эту карточку как работающий отчёт. |

Кнопка «Показать» ставит фильтр списка. Сам выпадающий фильтр списка эти пункты не содержит: они приходят со страницы мониторинга. См. [Списки записей](./lists).
