# Администрирование

Раздел для того, кто держит сервер Okkey. Он одинаков для тарифа «Бесплатный» и тарифа «Предприятие». Содержимое сейфов администратор сервера не читает: шифрование остаётся на устройстве пользователя.

Команды рассчитаны на каталог `~/okkey` и проект Compose `okkey`. Если вы задали `OKKEY_INSTALL_DIR`, перейдите в этот каталог. Имя проекта — имя каталога в нижнем регистре. Тома называются `<проект>_okkey-postgres`, `<проект>_okkey-redis` и `<проект>_okkey-minio`.

## Где что лежит

| Что | Где |
| --- | --- |
| Файл Compose и `.env` | Каталог установки, по умолчанию `~/okkey`. |
| Метаданные, пользователи, устройства | Том Postgres `okkey_okkey-postgres`. |
| Зашифрованные файлы | Том MinIO `okkey_okkey-minio`, в контейнере каталог `/data`. |
| Сессии и очередь писем | Том Redis `okkey_okkey-redis`. Записи сейфа там не хранятся. |
| Веб | Порт `8080`, если не меняли `WEB_PORT`. |
| API | `127.0.0.1:4000`, если не меняли `API_PORT`. |

В `.env` лежат `POSTGRES_PASSWORD`, `SESSION_SECRET`, `JWT_SECRET`, `EMAIL_DEAD_LETTER_SEAL_KEY` и `MINIO_ROOT_PASSWORD`. Копия без этого файла не оживит старые данные.

## Что делать дальше

1. Снимите [копию](./backup-restore.md) и один раз восстановите её на пробу.
2. Обновляйтесь по странице [Обновление](./upgrade.md). Перед этим снова снимите копию.
3. Возврат к прошлым данным — на странице [Откат](./rollback.md). Смена тега образа сама по себе уже применённые миграции базы не отменяет.

## Как проверить

```bash
cd ~/okkey
docker compose -p okkey -f docker-compose.prod.yml --env-file .env ps
curl -fsS http://127.0.0.1:4000/health
```

`"status": "ok"` значит, что API отвечает на этой машине.
