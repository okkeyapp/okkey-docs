# Откат

Откат возвращает сервер к данным и образам, которые были до обновления. Он одинаков на тарифе «Бесплатный» и на тарифе «Предприятие».

Смена `OKKEY_IMAGE_TAG` на старый тег не снимает миграции, которые новый API уже записал в `schema_migrations`. Скриптов, которые откатывают эти SQL-файлы, при старте нет. Путь назад — копия, снятая до обновления: дамп Postgres, архив MinIO, файл `.env` и `docker-compose.prod.yml` той версии.

Содержимое сейфов по-прежнему открывается мастер-паролем на устройстве. Серверная копия без прежнего `.env` запечатанные секреты не откроет.

## Шаги

1. Убедитесь, что есть дамп, архив MinIO и `.env` с момента до обновления. См. [Копирование и восстановление](./backup-restore.md).
2. Остановите стек.

```bash
cd ~/okkey
docker compose -p okkey -f docker-compose.prod.yml --env-file .env down
```

3. Верните `.env` и `docker-compose.prod.yml` из той копии. В `.env` должен стоять прежний `OKKEY_IMAGE_TAG`, тот же `POSTGRES_PASSWORD` и тот же `SESSION_SECRET`.
4. Скачайте образы этого тега и проверьте подписи `api`, `web` и `worker`, как в разделе [Версии и релизы](./upgrade.md#версии-и-релизы).
5. Поднимите Postgres и восстановите дамп. Восстановите том MinIO из архива. Redis верните, только если в копии он был и вам нужны старые сессии и очередь писем. Команды восстановления — на странице [Копирование и восстановление](./backup-restore.md).
6. Запустите стек без `OKKEY_RESET_VOLUMES`:

```bash
docker compose -p okkey -f docker-compose.prod.yml --env-file .env up -d
```

`OKKEY_RESET_VOLUMES=1` стирает тома. Для отката он не подходит.

Если каталог не `~/okkey`, имя проекта в `-p` — имя каталога в нижнем регистре. Имена томов начинаются с него же.

## Как проверить

```bash
cd ~/okkey
docker compose -p okkey -f docker-compose.prod.yml --env-file .env ps
curl -fsS http://127.0.0.1:4000/health
```

В ответе `"status": "ok"`. Откройте веб по `PUBLIC_APP_URL` и разблокируйте хранилище. Запись, которая была до обновления, на месте. Код входа при ненастроенной почте снова виден в логе воркера. См. [Почта](../install/email.md).

Если перед обновлением вы меняли `SESSION_SECRET`, пароль SMTP в «Почте сервера» может не прочитаться. Введите его снова или нажмите «Удалить сохранённый пароль». См. [Почта](../install/email.md).

## Частые ошибки

| Что видно | Что сделать |
| --- | --- |
| API не становится healthy, в логе `password authentication failed` | `.env` не от этого тома Postgres. Возьмите пароль из копии, вместе с которой снимали том или дамп. |
| Второй фактор или пароль SMTP не открываются | `SESSION_SECRET` новый. Верните секрет из той же копии, что и база. |
| `DROP DATABASE` не выполняется | Соединение ещё держит базу. Повторите `pg_terminate_backend` со страницы копирования и снова удалите базу. |
| `up` предупреждает, что том уже существует и без меток Compose | Том создавали через `docker volume create`. Удалите его и создайте через `docker compose … create`, как на странице копирования. |
| Старый образ не совпал с подписью | Не запускайте его. Проверьте тег и дайджест командой cosign. |
| После старого тега API снова отказывается обновлять схему | База не похожа на известную отметку миграций. Верните дамп целиком, а не смешивайте новый том со старым образом. |
